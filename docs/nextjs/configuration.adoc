The adapter reads its connection and mapping settings from Next.js environment variables. Keep environment-specific values outside committed files when they contain secrets.

== Server variables

[%header,cols="1,1,3"]
|===
| Name | Required | Purpose

| `+ENONIC_API+`
| Yes
| Absolute URL of the Enonic XP API root, for example `http://localhost:8080/api`.

| `+ENONIC_APP_NAME+`
| Yes
| XP application key that owns the content types and component descriptors used by the project.

| `+ENONIC_MAPPINGS+`
| Yes
| Comma-separated `locale:project/site-path` mappings. The first is the default.

| `+ENONIC_API_TOKEN+`
| Yes, for preview and revalidation
| Shared secret used by the starter's proxy and protected API routes. It must match the Next.XP app configuration.

| `+GUILLOTINE_API+`
| No
| Guillotine API appended to `+ENONIC_API+`. Default: `com.enonic.app.guillotine:graphql`.

| `+ENONIC_MEDIA_CDN+`
| No
| Base URL for images and attachments. Default: `+ENONIC_API+`.

| `+ENONIC_ADMIN+`
| No
| Enonic admin URL, used for CORS when the admin is served from a different domain than the API. Default: the origin of `+ENONIC_API+`.

| `+ENONIC_LOGGING+`
| No
| Enables adapter diagnostic logging when configured by the application.
|===

[source,text]
----
ENONIC_API=https://xp.example.com/api
ENONIC_APP_NAME=com.example.site
ENONIC_MAPPINGS=en:website/site,no:website-no/site
ENONIC_API_TOKEN=replace-with-a-long-random-value
----

Development-only diagnostics and catch-all behavior are enabled when `NODE_ENV` is `development`, as under `next dev`.

== Server and client configuration

The v6 starter uses the server variables above and does not require `+NEXT_PUBLIC_+` copies. Importing a common adapter export in a client component does not by itself require exposing the environment configuration.

For custom client components, pass the required non-secret data or resolved URLs from the server. The adapter still supports optional public values for client-side helpers that read configuration, but these are not part of the standard starter setup.

Never publish `+ENONIC_API_TOKEN+`. Values prefixed with `+NEXT_PUBLIC_+` are embedded in browser JavaScript.

== Next.js configuration

The starter configures `@phrases` for both webpack and Turbopack, transpiles `@enonic/nextjs-adapter`, supplies a Content Security Policy compatible with Content Studio embedding, sets CORS headers allowing the XP admin origin, and defines `env.BUILD_ID`, used to detect a draft cookie issued by another build. Preserve those settings when merging the integration into an existing Next.js application.

See <<../starter/configuration#,Starter configuration>> for the complete connection between Next.js and the XP app.
