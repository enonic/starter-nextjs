= App configuration
:toc: right
include::../.variables.adoc[]

Configure front-end servers in `<xp-home>/config/com.enonic.app.nextxp.cfg`. Each server has a name, URL, and shared secret.

== Properties

[source,properties]
----
nextjs.default.url=http://localhost:3000
nextjs.default.secret=replace-this-secret

nextjs.production.url=https://www.example.com
nextjs.production.secret=replace-this-production-secret
----

[%header,cols="2,3"]
|===
| Property | Purpose

| `nextjs.<name>.url`
| Base URL used for preview, URL mappings, and revalidation requests.

| `nextjs.<name>.secret`
| Secret used to encrypt requests to the protected Next.js endpoints. It must equal `+ENONIC_API_TOKEN+` in that deployment.
|===

Names are case-insensitive in the configuration parser and appear in the site's **Configuration name** selector.

NOTE: Use `default` name to override the default values.

== Defaults

Without a matching configuration, the app falls back to:

[source,properties]
----
nextjs.default.url=http://localhost:3000
nextjs.default.secret=mySecretKey
----

These values are suitable only for local development. In production mode, the default URL is not allowed in Content Studio's Content Security Policy. Configure a unique secret in every shared or production environment.

== Network considerations

The URL is used by the XP server and by the editor's browser, which loads the preview directly. Use a hostname reachable from every XP cluster node and from editors' browsers. Avoid a trailing slash, use HTTPS outside a trusted local network, and ensure any intermediary forwards cookies and query parameters.

Configuration changes are read by the app without rebuilding it. Reopen or refresh the Content Studio preview after changing a target URL or secret. URL mappings fetched from the front end are cached per project for up to 24 hours.
