= Release Notes
:toc: right

== Next.XP 6

Next.XP 6 replaces the XP-side preview proxy with a preview widget that loads the Next.js front end directly, and moves to Guillotine 9. It requires Enonic XP 8.1 or later.

=== Direct Content Studio preview

The Next.XP app 6 adds a "Next.js Preview" widget to Content Studio. It fetches URL mapping rules from the front end's new `/api/mappings` endpoint, caches them per project, resolves the selected content item to a Next.js URL, and lets Content Studio load that URL directly from the Next.js server. The preview works without adding the app to the site; add it to enable revalidation or to select a named configuration.

The `/api/renderable` endpoint is no longer used.

=== Live page editing

Next.js-rendered pages now support Content Studio's live page editing: component drag-and-drop, inline text editing, and click-to-select.

=== Encrypted requests

Requests from XP to `/api/preview`, `/api/mappings`, and `/api/revalidate` carry an `xp` parameter encrypted with the shared secret, instead of a plain token. `ENONIC_API_TOKEN` is still required and is now the encryption key. The adapter exports `encryptParams()` and `decryptParams()`.

=== Proxy-driven draft mode

The starter's `src/proxy.ts` validates the `xp` parameter, enables draft mode through `/api/preview` when the draft cookie is missing or belongs to another build (`BUILD_ID` in `next.config.js`), and redirects to the same URL without the parameter. Draft mode alone switches the adapter to `edit` render mode.

The default locale no longer has a URL prefix: the proxy rewrites prefix-less URLs to the default locale's internal route and redirects `/<default locale>/...` to `/...`.

=== Automatic Content Studio CSP allow listing

The Next.XP app adds its configured front-end origins, together with `'self'`, to Content Studio's Content Security Policy (`frame-src`, `connect-src`, and `style-src`). Manual `contentSecurityPolicy.header` configuration of Content Studio is no longer needed. The default `http://localhost:3000` origin is allowed in dev mode only.

=== CORS headers

The starter's `next.config.js` sets CORS headers allowing the XP admin origin, taken from the new optional `ENONIC_ADMIN` variable or the origin of `ENONIC_API`.

=== Guillotine 9

* Queries pass `siteKey`, `project`, and `branch` to the `guillotine()` field instead of relying on the endpoint URL. The adapter supplies these variables to every registered query.
* `imageUrl`, `mediaUrl`, `attachmentUrl`, and `pageUrl` return objects and require a subselection. The `type: absolute` argument and the `type` field of the `processHtml` input are removed.

=== New API URL format

`ENONIC_API` points to the XP API root (for example `http://localhost:8080/api`) instead of the `/site` endpoint. The Guillotine endpoint is `ENONIC_API` + `/` + `GUILLOTINE_API` (default `com.enonic.app.guillotine:graphql`). Media URLs are built from the new optional `ENONIC_MEDIA_CDN`, defaulting to `ENONIC_API`; no `media.defaultBaseUrl` configuration is needed in XP.

=== Adapter v6

* Added `imageUrlQuery()`/`imageUrl()`, `mediaUrlQuery()`/`mediaUrl()`, `attachmentUrlQuery()`/`attachmentUrl()`, and `pageUrlQuery()`/`pageUrl()`.
* Added `localizeMappings()`, `encryptParams()`, `decryptParams()`, `getContentBranch()`, `richTextFragments()`, `withRichTextFragments()`, and the `FROM_XP_PARAM` constant.
* Added the `DraftModeIndicator` view.
* `richTextQuery()` selects the full `imageUrl`, `mediaUrl`, and `pageUrl` objects for images and links, and `RichTextView` rewrites them to absolute media URLs and locale-prefixed routes.
* Removed `getContentApiUrl()`, `getUrl()`, `getAsset()`, and `UrlProcessor`.
* `MetaData.apiUrl` is replaced by `branch`, `project`, and `site`.
* Query and variables functions receive a `GlobalVariables` object instead of the content path.
* `BaseMacro` no longer accepts `renderInEditMode`, and `RichTextView` no longer accepts `renderMacroInEditMode`; macros render in Content Studio as on the public site.
* `IS_DEV_MODE` follows `NODE_ENV` instead of the `MODE` variable.

== Next.XP 5

This is an XP8 compatibility release, allowing you to upgrade to XP8 with minimal changes to your Next.XP 4 project.

=== Enonic XP 8 support

Next.XP is now based on Enonic XP 8:

* Application schemas use the new YAML format in `src/main/resources/cms/` (previously XML in `src/main/resources/site/`)
* Guillotine 8 is now used — existing GraphQL queries work unchanged

=== Adapter v5

`@enonic/nextjs-adapter` v5 is now used, requiring Node.js 24.15.0+ and npm 10.9.2+.
Media links in rich text now use the `+/_/media:image/+` and `+/_/media:attachment/+` URL format served by XP 8.

== Next.XP 4

=== Framework upgrades

* Next.js 16 and React 19
* ESLint 9 with flat config (`eslint.config.mjs`)
* `@enonic/nextjs-adapter` v4

=== Proxy replaces middleware

The `src/middleware.ts` file has been replaced by `src/proxy.ts`, following the Next.js 16 convention.
Route params are now asynchronous (`Promise`) and must be awaited.

=== Default port

The production server (`npm run prod`) now starts on the default port 3000 instead of 4242, so Content Studio preview works in both dev and prod modes without extra configuration.

== Next.XP 3

=== App router structure

Next.js' app router is now default folder structure for Next.XP projects.
This includes support for pages and layouts, route groups, parallel and intercepting routes.

=== Improved Next.js localization

In addition to localization of content, Next.XP now supports localization of static texts both in client and server components.
Use `useLocaleContext` hook in client-side components and `I18n` in server-side ones.

=== Major nextjs-adapter refactoring

In order to support the new app router, `@enonic/nextjs-adapter` has been substantially refactored.

=== Other improvements

* `next/Link` component is now used for all internal links
* `getAsset` method for static assets
